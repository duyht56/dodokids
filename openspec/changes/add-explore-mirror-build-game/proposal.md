## Why

Khám phá (Explore) has spatial games for arranging (`stack_tower`) and navigating
(`route_planner`), but nothing that trains SYMMETRY — the ability to see that one
half of a picture is the mirror of the other and to complete it. Left-right
reflection is a foundational spatial-reasoning skill for a 4–6-year-old (folding a
shape, matching two halves) and is distinct from the classification and pattern
skills the catalog already covers.

The Explore engine already has everything needed to build it offline and
stateless: the odd_one_out View-drawn, colour-blind-safe token vocabulary
(`ODD_ONE_OUT_COLORS` / `ODD_ONE_OUT_SHAPES`) for the ON-cell fill and the
`numberUtils` seeded RNG / shuffle for a deterministic pattern. A new game reuses
both and adds only a generator, an independent reflection validator and a
tap-to-toggle "build the mirror" renderer with a "Xong" submit.

## What Changes

- **One new local, offline, stateless game** registered end to end (contract
  codes in all three packages, mobile registry/variety/renderer map/thumbnail/
  catalog group, kido-server registry, a conformance script
  `npm run test:explore-mirror-build`, a kido-server spec and this capability
  spec): `mirror_build` ("Soi gương").
- A grid of R rows × (2·C) columns split by a vertical mirror line down the
  middle. The LEFT C columns are pre-filled with a seeded pattern (some cells ON,
  in ONE colour and ONE shape); the RIGHT C columns start empty. The child taps a
  right-side cell to toggle it ON (tap again to turn it OFF) and submits "Xong".
- The board is correct ONLY when the right half is the EXACT left-right mirror of
  the left half: the right cell at column (C + 1 + k) reflects the left cell at
  column (C − k) — i.e. right column c mirrors left column (C − 1 − c) — matching
  ON/OFF (and, since a puzzle uses one colour and one shape, colour/shape trivially
  match once the cell is ON). Tap-only, no drag.
- A **deterministic seeded generator** and an **INDEPENDENT validator** that,
  re-derived from the VISIBLE left pattern alone, proves the recorded solution's
  right half equals the exact reflection, that the puzzle is non-trivial (≥ 1 ON
  cell and not all cells ON), that a single colour and shape from the shared
  vocabulary are used and the recorded answer is exactly the solution's ON right
  cells, on top of a byte-identical replay-by-seed check.
- A renderer that taps a right cell to toggle it and submits "Xong": correct →
  Đô Đô cheers and the completed symmetric picture pulses (native driver, instant
  under reduced motion); wrong → a gentle no-mark retry (mascot "think",
  `onTryAgainSound`, `onAnswer(false)` raises the play screen's support level, the
  selection stays editable, nothing is marked, the run never ends); `supportLevel`
  1 highlights the next expected mirror cell (a subtle anchor) and 2 dims
  impossible cells (right cells whose left mirror-partner is OFF), never
  auto-filling the answer; emoji-free UI.
- A progressive one-board-per-level L1→L5 run (like `odd_one_out`): no XP, streak,
  countdown or lose state; levels scale the grid
  (3×(2·2) → 4×(2·4)) and the pattern density.
- Best-effort audio: one new phrase clip `mirror_build_reflect` and the
  `game_mirror_build` catalog name added to `promptAudio.ts` and mirrored in
  `kido-pipeline/src/explore/exploreAudioInventory.ts`; the on-screen prompt and
  the pre-filled left half carry the task and stay authoritative, and a missing
  clip never blocks play. No audio is regenerated by this change.

## Capabilities

### New Capabilities

- `explore-mirror-build-game`: left-right symmetry puzzles with a deterministic
  generator, an independent "the right half is the exact reflection of the left
  half" validator, a non-trivial guarantee, a support level that anchors and dims
  without auto-filling, and a progressive L1→L5 run.

## Impact

- Mobile Explore only: a new `games/mirrorBuildGame.ts`, a new
  `renderers/MirrorBuildRenderer.tsx`, the `mirror_build` code added to
  `EXPLORE_GAME_CODES` (docs contract + mobile + server types), and registration
  in `registry.ts`, `variety.ts`, `rendererRegistry.tsx`, `thumbnails.ts` and the
  catalog group table; one phrase entry plus the game-name entry in
  `promptAudio.ts` (mirrored in the pipeline inventory) plus a `mirrorBuildKeys`
  builder. It reuses the odd_one_out colour/shape vocabulary and the numberUtils
  seeded RNG with no changes to either.
- kido-server: `mirror_build` added to `PUBLIC_GAMES` and the local bundled
  `ROUND_2_GAMES` map, so the public catalog now advertises nineteen games; no
  runtime generation on the server (local game).
- No schema, curriculum, progress, reward, analytics or Explore-history change
  (`explore-stateless-privacy`): all play state is memory-only.
- App bundle grows by one short best-effort clip; until the pack is approved and
  exported the new key resolves to silence and the on-screen prompt is the
  authoritative instruction.

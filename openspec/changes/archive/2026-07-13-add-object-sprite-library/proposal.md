# Proposal: add-object-sprite-library

> Part of the visual-asset-system architecture umbrella
> (`docs/KIDO_VISUAL_ASSET_SYSTEM.md`). Must land before
> `add-transform-based-visuals`, which depends on canonical sprite identity and
> `transformPolicy`.

## Why

Real-world `LIB-*` assets are inferred from an asset-id slug and generated by
Imagen when missing (`resolveLibraryAsset`), but the pipeline does not perform
real background removal — `image-processing.ts` only resizes and converts to
WebP. Mobile therefore masks baked-in backgrounds with a sticker chip. The same
reusable object vocabulary is needed by English theme vocabulary and by math
(`count_tap`, quantity/size/length comparison), so Kido needs one canonical,
reusable, transparent object-sprite system with structured identity and verified
alpha, held for human review before reuse.

## What Changes

- Add a Generated Object Sprite Library with canonical structured identity:
  theme, object, color, variant, view, and style version. Lookups use structured
  fields and a unique compound identity key, not a single prompt string.
- Generate a missing object once, remove its background into a true alpha sprite,
  run deterministic alpha/crop quality checks, and hold it at `pending_review`
  until Human Gate approval. Concurrent requests coalesce on one identity.
- Add a replaceable `removeBackground` interface with an edge-connected
  solid-background first implementation; failed removal goes to an error/review
  state and is never marked transparent/approved.
- Store canonical identity, alpha/crop metadata, transform-eligibility, style
  version, generation revision, and structured failure/rejection reasons on the
  `assets_library` schema, with uniqueness for the logical identity.
- Preserve legacy asset IDs and non-alpha images as readable; add structured
  metadata only where backfill is unambiguous, never overwriting approved images.

## Capabilities

### Modified Capabilities

- `visual-asset-library`: adds generated-sprite identity, generate-once-review,
  and verified transparent output. (Extends the capability introduced by
  `materialize-primitive-assets`.)
- `content-pipeline-flow`: missing-sprite resolution coalesces a review workflow;
  Imagen sprites require human approval before reuse/publish.
- `mongoose-schemas`: `assets_library` gains canonical identity, alpha/crop
  metadata, transform eligibility, generation revision, uniqueness, and audit.

## Impact

- **kido-pipeline**: library-asset model/indexes, structured-identity resolver,
  isolated-object prompts, `removeBackground` stage + alpha QA, Human Gate sprite
  preview, publish staging, and tests.
- **kido-server**: mirrored asset identity/alpha fields and publish validation.
- **mobile**: alpha sprites usable without the sticker chip (chip retained only
  as a legacy/non-alpha fallback).
- **docs**: asset authoring rules and image/asset pipeline docs.
- **data**: additive migration/backfill of unambiguous identities; approved
  images are never overwritten automatically.
